# Public task help

The public help center is built with MkDocs at `/ayuda/`. Its two primary entrances are `/ayuda/caja/` and `/ayuda/negocio/`; `/ayuda/clientes/` supports customers and `/ayuda/problemas/` collects common problems. It contains 81 Spanish pages, including short task guides for all 30 modern owner routes and two printable checklists. `/guias/` remains the separate editorial publication.

## Public/private boundary

Only `help/docs/` is published. The MkDocs configuration explicitly uses that directory; it never builds the repository's `docs/`, security notes, runbooks, evidence or source manifests. `public/ayuda/` is checked in so production requires neither Python nor a build-time package download. `help/evidence/owner-ui.json` records the actual local demonstration text used for verification; it is not published.

Task guides include prerequisites, exact relevant UI labels, ordered steps, expected results, troubleshooting, escalation and reviewed date. Their author–date citation and APA-style reference identify PF itself as the primary software source. No external study is invented to support a button instruction. Steps describe browser behavior; they do not establish native app behavior. Staff practice links to the existing saved rehearsal in `/equipo/escaner/#staffServiceBriefing`; no parallel training implementation was introduced.

## Build and verify

Use Python 3.13 with an isolated virtual environment. All MkDocs dependencies are pinned in `help/requirements.txt`.

```sh
python3 -m venv /tmp/pf-help-venv
/tmp/pf-help-venv/bin/python -m pip install -r help/requirements.txt
/tmp/pf-help-venv/bin/python help/scripts/build.py
/tmp/pf-help-venv/bin/python help/scripts/build.py --check
/tmp/pf-help-venv/bin/python help/scripts/test-guards.py
```

The host needs Python's `venv`/`ensurepip` support. The prepared environment for the November 16 review is `/tmp/pf-help-venv`; it was bootstrapped in isolation because this host lacked ensurepip. The repository does not depend on that path.

The strict build fails for missing navigation, undocumented modern owner routes, incomplete task structure, missing citations, changed reviewed implementation, expired reviews (90 days), missing source files, changed screenshots, broken generated links/anchors, missing semantic landmarks, inline executable content, or a search index that omits a page. `--check` builds in a temporary directory and compares every generated byte without rewriting the checkout. A fixed `SOURCE_DATE_EPOCH` makes the build reproducible; update it deliberately with a reviewed publication change. Four regression tests deliberately introduce source drift, a broken link, inline code and a leaked Markdown source to verify that these protections reject them.

Node browser checks use the repository's pinned Playwright, Express and Helmet dependencies, plus `axe-core` from `web/merchant/node_modules`:

```sh
node help/scripts/browser.mjs
```

Optional environment variables are `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` and `PF_HELP_ARTIFACTS`. The November 16 run used Node 24.22.3 and Chromium 1254. It passed 18 checks at 1440, 390 and 320 CSS pixels: axe, overflow, QR search, accented queries, safe query handling, keyboard navigation, direct search URLs, screenshot loading, print layout, content without JavaScript, search without Worker, and no uncaught browser errors, CSP violations or external requests. Evidence was written to `/tmp/pf-help-review/`; it includes desktop/mobile screenshots and `lista-del-turno.pdf`. These are local checks, not production deployment verification.

## Updating a guide

1. Read the actual current screen and its implementation. Edit the relevant Markdown under `help/docs/`; preserve its task structure and source metadata. Recheck statements about pending operations, permissions, points, messages and evidence.
2. Update the guide's `reviewed` date and references after reviewing it. Add any new page to `help/mkdocs.yml`.
3. If a tracked source changed, review every guide listing it, then intentionally record the baseline:

   ```sh
   /tmp/pf-help-venv/bin/python help/scripts/review-sources.py --record-reviewed
   ```

   This command records hashes; it does **not** review content and must not be run merely to silence the build. The 22 button contracts in `help/reviewed-sources.json` also require their labels to appear in both the UI source and the guide.
4. Rebuild, run `--check`, and run the browser checks for a UI or search change. Commit the Markdown and generated output together. Changes to `/soporte` made during integration require rechecking the support guide and intentionally updating its tracked source hash.

The review date is rendered from each page's metadata. PF permission and plan restrictions remain enforced by the product; a public guide or direct link does not grant access.

## Theme and reading design

The maintained built-in `mkdocs` theme supplies the supported MkDocs theme contract and official search plugin. `help/theme/` overrides its page template and 404 page; focused CSS preserves PF's warm paper, terracotta, Inter, Bricolage Grotesque and Fraunces. The search client directly uses MkDocs' bundled Spanish Lunr worker, accepts two-character queries such as `QR`, and falls back to the same public search index if Workers are unavailable. Queries remain in the browser; no search analytics or third-party request is added. The site is not an offline download or an operational cache.

The reference center [Garita Ayuda](https://garitagt.com/ayuda/) informed the role/task organization, screenshots, short prerequisites and problem escalation. Official [MkDocs theme documentation](https://www.mkdocs.org/user-guide/choosing-your-theme/) supports the built-in-theme choice. The [Material project](https://squidfunk.github.io/mkdocs-material/) announced end of life on May 5, 2027; this implementation therefore remains MkDocs with its built-in theme and does not silently adopt Zensical. Reviewed November 16, 2026.

The owner's prose references were inspected at [Exposición I](https://edu.tallerlumiere.com/tecnica/exposicion-i/) and [Albert Renger-Patzsch](https://edu.tallerlumiere.com/perfiles/albert-renger-patzsch/): explain a distinction plainly, then take the reader through concrete steps. No author experiences, claims or photographic examples were transferred to PF. The manuals remain original operational prose.

Impeccable context was loaded once and the final mechanical detector was run. Its font warnings concern the owner's explicitly retained faces. Its flat-hierarchy warning came from failing to resolve the root-absolute linked stylesheet in a Jinja template; actual rendered headings are materially larger than body text. Axe and visual review checked the rendered surface. Independent editorial/implementation review is performed by the parent release workflow before deployment.

## Server integration contract

- Serve the complete `public/ayuda/` subtree publicly, including nested `index.html`, WebP, CSS/JS, `search/worker.js`, Spanish Lunr files, `search/search_index.json`, and sitemap files.
- `/ayuda` redirects to `/ayuda/`; task directory URLs use trailing slashes. An unknown help page should return the dedicated 404 document with status 404, not an authenticated application or SPA fallback.
- Keep `/ayuda/sitemap.xml` discoverable from the main robots/sitemap integration. Public help is indexable; operational routes retain their existing indexing/authentication controls.
- CSS, fonts, images, JavaScript and Worker all load from the same origin. CSP needs `script-src 'self'`, `style-src 'self'`, `font-src 'self'`, `img-src 'self'` and `worker-src 'self'` (or the equivalent existing fallback). No inline allowance, CDN, eval, new backend API, storage permission or service worker is needed.
- Root-absolute links use `/equipo/ingresar/`, `/equipo/escaner/`, `/mi-tarjeta/`, `/negocio/#<modern-fragment>`, `/preferencias-de-mensajes/`, `/privacidad`, `/guias/`, `/soporte`, `/estado` and `/calculadora`. The latter dynamic/public routes are integration contracts: the parent verifies their actual server responses.
- Do not expose `help/` itself or repository `docs/`. Native application features, dependencies, versions and build triggers remain untouched.
