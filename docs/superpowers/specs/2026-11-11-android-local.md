# Android builds on PF's Linux VM

The owner approved moving Android compilation from Codemagic to the existing Linux VM. This authorizes local build infrastructure and a verification build, not changes to customer features, dependencies, app versions, iOS, or publishing a new Play release. Preserve current Android package com.puntosfieles.customer, version name 0.1.0 and verification version code 13; future Play uploads require a deliberately chosen higher code. No cloud builds or OTA updates.

Use a dedicated Docker toolchain and an isolated copy of the app, reusing Expo prebuild, the checked-in Gradle/signing helper and artifact validators. Pin Node 22.22.2, Java 17 for Gradle, SDK/build-tools 36, NDK 27.1.12297006 and CMake 3.22.1. Download Google command-line tools with their official published checksum. SDK/bootstrap runtime may use a separate Java version if required by the pinned tooling; app Gradle remains Java 17. npm ci uses the existing lockfile. No source directory, iOS project or lockfile may be regenerated in place.

Provide manual doctor/setup/build commands. Keep SDK, npm and Gradle caches outside the repository. Fail before large downloads when available disk is below 25 GiB or before builds when available RAM is below 4.5 GiB; these are conservative PF operating thresholds, not vendor minimums. This VM has 2 CPUs/8 GiB RAM and a 30 GiB disk with 1.6 GiB free at assessment. Storage expansion or a different build host is required for full compilation. An asynchronous storage question is pending. Do not delete rollback images, database volumes, documents or other users' work to force a build.

Run one build at a time with a filesystem lock, at most one CPU and 4 GiB RAM, no Docker socket/privilege/production database credentials. Build from a private source snapshot with manifest hashes; exclude generated directories, dependencies and secret files. Containers receive only the existing Android upload keystore/password as read-only files and a nonsecret alias. Never place credentials in Docker image layers, CLI arguments, logs or artifacts. Reuse the existing signing identity. Output only APK/AAB, checksums, safe validation reports and a build provenance record; no automatic upload.

Remove the manual Android workflow from the active Codemagic YAML after preparing the local replacement; retain iOS workflows byte-for-byte. Documentation must clearly distinguish prepared tooling from actual successful native compilation and device acceptance. Native app tests, lint/typecheck, meaningful runner guard/signing/build tests, review and one local full signed verification build (once storage permits) establish acceptance. Check live PF service health during/after a build.
